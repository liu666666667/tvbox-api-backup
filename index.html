回顾项目结构和逻辑：

  1. api下载.yml (工作流B): 负责读取 api_list.json 或 apilinks.txt（根据代码实际逻辑，之前已确认是读 api_list.json），抓取源并下载基础 JSON 文件。这是第一步，必须有新原料。

  2. ry下载.yml (工作流A): 负责下载特定的本地包或资源。虽然它也存在，但对于仅仅添加几个 JSON 接口源来说，它不是必须马上跑的，不过它在设计上是抓取后的下一步。

  3. 接口处理扫描工具.yml (工作流C): 负责对抓取到的所有文件进行筛选、过滤（比如只留 type 0/1）、合并，最终生成 海量采集聚合接口.json 等文件。这是最后一步，负责产出最终结果。

所以，最严谨且必须的顺序是：
api下载.yml -> 接口处理扫描工具.yml

为了帮用户彻底理清，我需要把这几个工作流的作用、依赖关系以及为什么必须按这个顺序执行讲清楚。同时，提醒用户不要漏掉（或者弄错）执行的关键点。

在这个项目里，所有的 Action 都是为了最终生成你需要的聚合接口而服务的。虽然项目里有几个不同的 yml 文件，但针对你现在“加了新源，想让它生效”这个目的，你只需要按严格的先后顺序执行两个核心工作流。

正确的执行顺序是：先抓取 ➡️ 后加工。

🥇 第一步：api下载.yml（抓取原料）

  • 它的作用：它是“采购员”。它会去读取你刚刚修改的 api_list.json，然后去网上把你写的那些源（肥猫、小鱼干、饭太硬等）的数据抓下来，生成一个个单独的原始 JSON 文件。

  • 什么时候跑：只要你在 api_list.json 里增加了、删除了或修改了任何一个源，都必须先跑这个。

  • 如果不跑：后面的步骤拿不到新原料，你加的源绝对不会出现在最终结果里。

🥈 第二步：接口处理扫描工具.yml（加工成品）

  • 它的作用：它是“加工厂”。它不看你的 api_list.json，它只盯着第一步抓回来的原料。它会进行过滤（比如剔除坏链、只留特定 type 的站点），然后把所有合格的站点合并，最终生成 tvbox/海量采集聚合接口.json。

  • 什么时候跑：必须等第一步跑完且变绿之后，再运行这个。

  • 如果不跑：你填给影视仓的聚合接口依然是旧的内容，不会更新。

🧐 另外还有一个 ry下载.yml 是什么？

项目里可能还有一个 ry下载.yml（有些版本叫这个）。它的作用通常是下载一些体积较大的“本地包”或者特定的资源。如果你只是添加普通的网络接口源，这个完全可以不跑，或者把它放在第一位跑（它和接口抓取不冲突）。

📝 你的标准操作流程（保姆级）

  1. 在 api_list.json 里改好代码，点击 Commit changes 保存。

  2. 点开顶部的 Actions 标签页。

  3. 左侧点击 api下载.yml。

  4. 右侧点击 Run workflow（下拉选你的 main 分支），点击绿色的运行按钮。

  5. 等待 1-3 分钟，刷新页面，看到 api下载.yml 这一条变成了绿色对勾。

  6. 左侧点击 接口处理扫描工具.yml。

  7. 右侧点击 Run workflow，点击绿色的运行按钮。

  8. 再等它变绿。搞定！现在去你的 tvbox/ 目录看，新文件就生成了。

⚠️ 切记：绝对不能两个同时点，或者先点加工再点抓取。必须等第一个跑完出结果，第二个才有东西可以加工。
